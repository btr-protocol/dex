# Cross-Chain Bridging

## 1. Overview

The protocol implements cross-chain bridging for BTR governance tokens (staked and unstaked) and eligible LP tokens using the ERC-7802 standard. Despite using LayerZero V2 in its current state, the bridge is designed to be messaging-protocol agnostic to support alternatives on upgrade (eg. Chainlink CCIP, Axelar GMP...).

## 2. Architecture

### 2.1. Components

1. **Bridge Contract** (`contracts/src/Bridge.sol`)
   - Standalone contract (not a pool module)
   - Implements LayerZero V2 OApp pattern
   - Manages token burn/mint on source/destination
   - Enforces daily rate limits per token

2. **ERC-7802 Tokens**
   - BTR, sBTR, and LP tokens implement `IERC7802`
   - Provides `crosschainBurn()` and `crosschainMint()` functions
   - Bridge has minter/burner roles

3. **LayerZero Integration**
   - Uses LayerZero V2 endpoint
   - Peer-to-peer bridge configuration
   - Native gas payment for cross-chain messages

## 3. Technical Details

### 3.1. Bridge Flow

#### 3.1.1. Outbound (Source Chain)

1. **Initiate Bridge**
   ```solidity
   bridge.bridgeViaLayerZero(token, dstEid, receiver, amount, options)
   ```

2. **Limit Check**
   - Check daily outbound limit (B64-encoded)
   - Verify token is supported and not paused
   - Reset counters if new day

3. **Burn Tokens**
   ```solidity
   IERC7802(token).crosschainBurn(user, amount, metadata)
   ```

4. **Send Message**
   - Encode: `(receiver, token, amount)`
   - Send via LayerZero with exact native fee
   - Emit `Bridged` event with nonce

#### 3.1.2. Inbound (Destination Chain)

1. **Receive Message**
   - LayerZero calls `lzReceive()`
   - Verify sender is trusted peer

2. **Limit Check**
   - Check daily inbound limit (percentage of outbound limit)
   - Reset counters if new day

3. **Mint Tokens**
   ```solidity
   IERC7802(token).crosschainMint(recipient, amount, metadata)
   ```

4. **Emit Event**
   - Log bridging with direction flag

### 3.2. Rate Limiting

The bridge uses **B64 float encoding** for gas-efficient daily limits:

```solidity
struct TokenConfig {
    uint64 limitOutB64;     // B64-encoded daily outbound limit
    uint64 bridgedOutB64;   // B64-encoded outbound volume today
    uint64 bridgedInB64;    // B64-encoded inbound volume today
    uint16 day;             // Day index for resets
    uint8  inRatio;         // Inbound limit ratio (% of outbound)
    uint8  flags;           // SUPPORTED | PAUSED | UNLIMITED
}
```

**Daily Limits**:
- **Outbound**: Absolute limit per token
- **Inbound**: Percentage of outbound (e.g., 120% = `inRatio: 120`)
- **Reset**: Automatically at UTC midnight

**Special Cases**:
- `UNLIMITED` flag: No limits enforced
- Missing config: Reverts with `TokenNotSupported`

### 3.3. Fee Quoting

```solidity
// Get exact native fee required
ILayerZeroEndpointV2.MessagingFee memory fee = bridge.quoteLZBridge(
    token,
    dstEid,
    amount,
    options
);

// Send with exact payment
bridge.bridgeViaLayerZero{value: fee.nativeFee}(...);
```

**Note**: Transaction reverts if `msg.value != fee.nativeFee` (exact payment required).

## 4. Configuration

### 4.1. Token Setup

Initial configuration (no timelock):

```solidity
bridge.setTokenConfig(
    token,
    1_000_000e18,  // 1M daily limit (raw)
    18,            // decimals
    120,           // 120% inbound ratio
    false          // not unlimited
);
```

### 4.2. Updating Configuration

Changes require **2-day timelock**:

```solidity
// Request update
bridge.requestConfigChange(
    token,
    2_000_000e18,  // New limit
    18,            // decimals
    150,           // New inbound ratio
    true,          // updateLimit
    true           // updateRatio
);

// Execute after 2 days
bridge.executeConfigChange(token);
```

### 4.3. Peer Configuration

Setting LayerZero peers requires **2-day timelock**:

```solidity
// Request peer setup
bridge.requestSetPeer(
    110,  // Arbitrum endpoint ID
    bytes32(uint256(uint160(arbBridgeAddress)))
);

// Execute after timelock
bridge.executeSetPeer(110);
```

## 5. Emergency Controls

### 5.1. Token Pause (Instant)

Bridge owner can instantly pause bridging for a token:

```solidity
bridge.pauseToken(token, true);  // Pause
bridge.pauseToken(token, false); // Unpause
```

**Effect**: Prevents both inbound and outbound bridging immediately.

### 5.2. Cancel Pending Operations

```solidity
bytes32 opId = keccak256(abi.encode(OpType.ConfigUpdate, token));
bridge.cancelOperation(opId);
```

## 6. Governance & Access Control

### 6.1. Bridge Owner

- **Initial**: DAO Council multisig (3-of-5 at launch)
- **Long-term**: Elected DAO council
- **Powers**:
  - Configure token bridging parameters
  - Set LayerZero peer addresses
  - Pause/unpause tokens (emergency)
  - Rescue stuck tokens
  - Migrate to new bridge infrastructure

### 6.2. Timelocks

| Operation | Delay | Bypass |
|-----------|-------|--------|
| Token config change | 2 days | No |
| Set peer address | 2 days | No |
| Pause token | None | N/A |
| Unpause token | None | N/A |
| Rescue tokens | None | No |

**Grace Period**: 3 days after timelock expires

## 7. Security Features

### 7.1. Trusted Peers

- Each chain has exactly one trusted peer bridge
- Inbound messages verified against `peers[srcEid]`
- Prevents unauthorized minting

### 7.2. Rate Limits

- Daily limits prevent catastrophic loss
- Separate inbound/outbound tracking
- B64 encoding prevents manipulation
- Automatic daily reset

### 7.3. Reentrancy Protection

- All external functions use `nonReentrant`
- Prevents callback exploits

### 7.4. Balance Verification

- Outbound: Burn before send
- Inbound: Verify peer before mint
- No intermediate custody

## 9. Integration Examples

### 9.1. Basic Bridging

```solidity
// Quote fee
ILayerZeroEndpointV2.MessagingFee memory fee = bridge.quoteLZBridge(
    BTR_TOKEN,
    ARBITRUM_EID,
    1000e18,
    "" // default options
);

// Approve bridge to burn
IERC20(BTR_TOKEN).approve(address(bridge), 1000e18);

// Bridge tokens
bridge.bridgeViaLayerZero{value: fee.nativeFee}(
    BTR_TOKEN,
    ARBITRUM_EID,
    bytes32(uint256(uint160(recipientAddress))),
    1000e18,
    "" // default options
);
```

### 9.2. Custom LayerZero Options

```solidity
// Increase gas limit for destination execution
bytes memory options = abi.encodePacked(
    uint16(3),  // option type
    uint128(300000)  // gas limit
);

bridge.bridgeViaLayerZero{value: fee.nativeFee}(
    token,
    dstEid,
    receiver,
    amount,
    options
);
```

## 11. Bridgeable Assets

At launch, the following assets are bridgeable:

1. **BTR**: Unstaked governance token
2. **sBTR**: Staked governance token
3. **LP Tokens**: Marked with `BRIDGEABLE_BIT` in risk config

Pool curators can enable bridging for their LP tokens via:

```solidity
riskConfig.flags |= BRIDGEABLE_BIT;
```

## 12. Migration Strategy

The bridge architecture supports migration to alternative bridges:

### 12.1. Adding New Bridge

1. Deploy new bridge contract
2. Grant mint/burn permissions to new bridge
3. Configure rate limits
4. Announce migration timeline
5. Disable old bridge after grace period

### 12.2. Supported Bridge Standards

- LayerZero V2 (current)

The bridge is designed to be messaging-protocol agnostic. Alternative providers (CCIP, Axelar, Hyperlane) can be added via timelocked operations if needed.

## 13. Best Practices

### 13.1. For Users

- Always quote fees before bridging
- Use sufficient gas limits for complex operations
- Verify destination address format (bytes32)
- Check daily limits before large transfers
- Monitor LayerZero message status

### 13.2. For Integrators

- Handle LayerZero delivery failures
- Implement retry logic for failed messages
- Cache fee quotes (valid for ~5 minutes)
- Support manual message execution via LayerZero scan
- Display estimated delivery time (5-30 minutes)

### 13.3. For Pool Operators

- Enable bridging only for liquid LP tokens
- Set conservative daily limits initially
- Monitor bridge activity via events
- Coordinate with bridge owner for config changes

## 14. Error Handling

| Error | Cause | Solution |
|-------|-------|----------|
| `TokenNotSupported` | Token not configured | Add via `setTokenConfig()` |
| `BridgePaused` | Token paused | Wait for unpause |
| `DailyLimitExceeded` | Over daily limit | Wait for daily reset or request limit increase |
| `ExactPaymentRequired` | Wrong msg.value | Use quoted fee exactly |
| `PeerNotConfigured` | Destination chain not set | Configure peer via `requestSetPeer()` |
| `UnauthorizedOrigin` | Message from untrusted peer | Contact DAO council |
